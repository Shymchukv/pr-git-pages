# Основи роботи з системою контролю версій Git

## 1. Системи контролю версій та Git

**Система контролю версій (VCS)** — це програмний інструмент, який відстежує зміни у файлах з часом, дозволяючи розробникам повертатися до попередніх версій, порівнювати зміни та працювати над одним проектом спільно.

**Git** — це найпопулярніша у світі розподілена система керування версіями, створена Лінусом Торвальдсом у 2005 році. На відміну від централізованих систем, у Git кожен розробник має на своєму комп'ютері повну локальну копію всієї історії проекту.

---

## 2. Основні можливості та переваги використання Git

* **Розподілена архітектура:** Можливість повноцінно працювати офлайн, оскільки вся історія зберігається локально.
* **Швидкість:** Операції (коміти, злиття, перемикання гілок) виконуються миттєво без потреби звернення до віддаленого сервера.
* **Гілкування (Branching):** Легке та швидке створення ізольованих гілок для розробки нових функцій, тестування ідей або виправлення багів без впливу на основний код.
* **Надійність та цілісність:** Усі зміни криптографічно захищені алгоритмом хешування SHA-1. Неможливо непомітно змінити файл або історію.
* **Спільна робота:** Легка інтеграція з платформами хостингу коду (GitHub, GitLab, Bitbucket) для командної роботи.

## 3. 10 базових команд роботи в системі Git

1. `git init`  
   *Ініціалізує новий порожній локальний репозиторій у поточній директорії.*
2. `git clone <url>`  
   *Копіює існуючий віддалений репозиторій (наприклад, з GitHub) на ваш локальний комп'ютер.*
3. `git status`  
   *Показує поточний стан робочої директорії: змінені, додані в індекс (staged) або невідстежувані файли.*
4. `git add <file>`  
   *Додає вказаний файл (або `git add .` для всіх файлів) до індексу, готуючи його до коміту.*
5. `git commit -m "Опис змін"`  
   *Фіксує підготовлені зміни в локальній історії репозиторію з коротким описом.*
6. `git push`  
   *Відправляє ваші локальні коміти на віддалений сервер, щоб інші розробники могли їх бачити.*
7. `git pull`  
   *Завантажує останні зміни з віддаленого репозиторію та автоматично зливає їх з вашою локальною гілкою.*
8. `git branch`  
   *Виводить список усіх локальних гілок. Поточна гілка позначена зірочкою (*).*
9. `git checkout <branch_name>`  
   *Перемикає робочу директорію на іншу існуючу гілку (або відкочує файли до певного коміту).*
10. `git merge <branch_name>`  
    *Зливає вказану гілку з тією гілкою, в якій ви знаходитеся зараз.*
